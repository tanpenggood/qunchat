# PRD: 暗号 —— 轻量级群聊

- **版本**: v1.0
- **状态**: 已实现
- **目标用户**: 需要即开即用、无注册流程的小群体即时沟通场景

---

## 1. 产品概述

"暗号"是一个零安装、零注册的网页群聊工具。输入昵称即可加入聊天室，适合临时团队、活动群组等轻量沟通场景。

### 核心价值主张

- **零门槛**: 打开网页 → 输入昵称 → 开始聊天
- **轻量**: 单 HTML 文件前端 + 单一 Go 二进制，内存占用约 5-10 MB
- **隐私友好**: 服务端不存储任何消息，纯实时转发

## 4. 技术需求

### 4.1 性能

| 指标 | 目标 |
|------|------|
| 单机并发连接 | >1000 |
| 消息延迟 | <100ms (LAN) |
| 服务端内存 | <50MB @ 1000 连接 |
| 前端打包体积 | 单个 HTML <50KB |

### 4.2 可用性
- 服务端断线自动重连（3 秒间隔）
- WebSocket 心跳保活（30 秒 ping）
- 消息无服务端存储，天然无数据泄漏风险

### 4.3 兼容性
- 浏览器: Chrome/Firefox/Safari/Edge 最新 2 个主版本
- 移动端: iOS Safari + Android Chrome
- 需支持 `BroadcastChannel` API（Chrome 54+, Firefox 38+, Safari 15.4+）

---

## 5. 约束

- 服务端不做消息持久化 —— 仅实时转发
- 无用户认证系统 —— 信任式匿名
- 无消息记录服务端备份
- 单房间模式 —— 所有已连接用户在同一聊天室
- 前端最大存储 500 条消息（localStorage 配额限制）

---

## 6. 设计决策

| 决策 | 选项 | 选择理由 |
|------|------|----------|
| 后端语言 | Go vs Node.js | Go 内存效率更高（goroutine 4-8KB vs JS 50-100KB/连接） |
| 通信协议 | WebSocket vs SSE vs Polling | WebSocket 全双工，延迟最低 |
| 存储策略 | 服务端 vs 客户端 | 客户端存储免除合规负担，天然隐私友好 |
| 前端框架 | 原生 vs React/Vue | 单页功能简单，零依赖减少体积 |
| 身份识别 | clientId vs 用户名 | clientId 持久化，改名不影响气泡归属 |

## 7. 数据模型

### WebSocket 消息

```
Message {
  cmd:       string  // "rename" 等命令（客户端->服务端）
  name:      string  // 发送者昵称 / "系统"
  text:      string  // 消息内容
  time:      number  // Unix 毫秒时间戳
  senderId:  string  // 发送者唯一标识
  online:    number  // 当前在线人数（服务端填充）
}
```

### localStorage 结构

| Key | Value | 说明 |
|-----|-------|------|
| `qunchat_messages` | `Message[]` | 最近 500 条消息 JSON |
| `qunchat_nickname` | string | 昵称 |
| `qunchat_client_id` | string | 持久化客户端 ID |

## 8. 风险与缓解

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| localStorage 满 | 新消息无法存储 | 超出时丢弃最旧 50% 消息 |
| WebSocket 断开 | 消息丢失 | 自动重连 + 3 秒间隔 |
| 恶意用户洪水攻击 | 服务端过载 | `ReadLimit` 限制单消息 8KB |
| BroadcastChannel 不支持 | 多标签不同步 | 降级为单标签模式（聊胜于无） |
